# Can a captured value survive a branch?

Preserving a value through a branch can recover a missing operand without silently performing a second read.  The useful idea from [Reko's SSA transform](https://github.com/uxmal/reko/blob/b5a4afc2cb85d8a426057b895bdf6be7644cfdb2/src/Decompiler/Analysis/SsaTransform.cs) is to ask **which definition reaches this use on each incoming edge**, not whether two expressions print alike.  A phi is a choice based on the edge actually taken; it does not evaluate both operands.  This is a narrow analysis recipe, not a general SSA implementation or a change to any family's default join barrier.

### Fill in one row per incoming edge

1. Name the block, consumer, slot/register, type, and evaluation instance.  Record each edge and its origin: conditional, fall-through, computed target, loop backedge, return, or independently supplied entry.  A linear listing and a single observed trace do not establish a complete predecessor set.  In an open region, mark the edge set incomplete.
2. Walk the definition forward on each edge to the **same consumer operand**.  Note copies versus fresh samples, any replacements, aliasing writes, unmodeled calls, stack rotations/resets, and width conversions.  Keep identity per value: an unchanged string slot is not proof of an integer stack depth or the selected channel.  Distinguish an immutable capture from a fresh lookup of a variable, memory, or device.  A later hardware change need not change a saved byte; it does make re-reading the device unsafe.
3. Forward an already captured value only when all feasible edges carry that one definition in the required representation, stack position, and dynamic instance.  Its definition must have executed on every path.  Keep the capture at its original site, especially for `PEEK`, `GET#`, `RND`, timers, and operations that can fail.  Do not print a second call to explain a later use.  Repeated execution at the same PC in a loop is not a single shared sample.  Leave unknowns at unmodeled entries, calls, and backedges unless separately resolved.
4. If the definitions differ, retain both paths or show an explicit conditional value.  Do not invent a fresh read, discard an arm, move a read across a branch, or present a conditional effect as an unconditional BASIC expression.  Before promoting a family rule, preserve instruction ownership, compare actual reader output, and test a genuine positive and a rejecting case from that family's dataflow.  If only a near-miss is available, keep the default conservative behavior.

### Two small discriminators

- **One read versus two.** `s = sample(); IF c THEN change_x; use(s)` permits forwarding `s` when neither path redefines it.  Replace `change_x` with `s = sample()` and it no longer does.  Same address, width, mnemonic, or returned byte does not imply same event.  The [runnable native counterpart](../../6502-disassembly/scripts/join_sample_probe.py) checks both arms against a changing synthetic port and also supplies a third entry that bypasses the first read.  Run `python3 scripts/join_sample_probe.py` from the `6502-disassembly` skill; it requires only the distribution's shared Python 6502 core.
- **Normalized input.** `s = GET_FILE_STRING(); IF s = "" THEN s = CHR$(0); n = ASC(s)`.  The nonempty arm keeps the earlier sample; the empty arm reaches `ASC` with a *different* value.  Preserve the conditional replacement and the single input event.  Even if a frontend correctly reconstructs this normalized string, a following `POKE` still needs independent evidence for its destination, integer depth, and value order.  Replacing `ASC(s)` with `ASC(GET_FILE_STRING())` is incorrect on both event-count and empty-string grounds.

For native register/flag effects, see the [6502 source audit](../../6502-disassembly/references/reko-source-audit.md).  For a new stack VM, first recover the actual opcode transfer functions and entry/exit contracts.  Neither Reko nor the synthetic example supplies those contracts.
